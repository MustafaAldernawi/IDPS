# 01 — PRD: Product Requirements Document

## ملخص المنتج

**اسم العمل:** Intelligent Refinery Operations Management & Production Forecasting System (مصفاة الزاوية).
**الفئة:** نظام معلومات تشغيلية ودعم قرار (Operational Decision Support System).
**المستخدم:** إدارة التشغيل، قسم الإنتاج، هندسة العمليات، التخطيط، والمختبر/الصيانة/السلامة بوصفها تكاملات أو مساهمين عند الحاجة.

### مشكلة العمل

مصادر تقريرية منفصلة وتدفق بيانات بطيء وتقارير مقارنة دورية يصعب معها تجميع أثر حالة الوحدات والتوقفات والإنتاج والفاقد والطاقة وتفسير انحرافات المستهدف. الملفات الواردة تثبت وجود بيانات شهرية للمقارنة وإنتاج/استهلاك وتوثيق؛ **لا تثبت وحدها أن واجهات DCS أو السجلات اليومية متاحة**.

### النتائج المستهدفة

- سجل موحد ومراجع للأصول والوحدات والمنتجات والأهداف الفعلية.
- تقليل الجهد اليدوي في إعداد مقارنة المستهدف/الفعلي.
- KPIs تراعي الوحدات والفترة وتعريف المنشأ.
- توقع يومي/نهاية شهر لكل منتج متاح، متى نجحت اختبارات ملاءمة البيانات.
- Reforecast بعد الحدث مع إعلان الفرضيات ومخاطر التأخر عن الهدف.
- وضوح حوكمة التعديل والاعتماد والتحسين الشهري للنماذج.

## أصحاب الأدوار ووظيفة كل قسم في السيستم

|---|---|---|---|
| الإنتاج | التشغيل الحقيقي، قياس الخام والمنتج والوردية | Production/Feed، حالة الوحدة، Event/Trip وETA مبدئية بحسب الصلاحية | متابعة الوردية، الانحرافات، صلاحية البيانات |
| هندسة العمليات | تحليل أداء الوحدات، Yield، الطاقة، Losses، Chemicals، Blend | توثيق تفسير الانحراف ومراجعة KPIs والمقارنات | Yield وKPI وforecast explanations |
| التخطيط | المستهدفات وجدول التوقفات والموارد | Targets بإصدارات، Planned Shutdowns، Availability Plan | تحقيق الخطة، أثر التوقفات، السيناريوهات |
| إدارة التشغيل | إشراف وتنسيق واعتماد القرار | اعتماد تقارير/تغيير أولوية حسب الصلاحية | Executive Dashboard/Alerts/Forecast Risk |
| المختبر (اختياري V1.1) | اختبار جودة المواصفات | Lab Results/Quality Samples | Blend & conformance |

## نطاق MVP

1. دخول وصلاحيات وإجراءات اعتماد وتدقيق.
2. جداول مرجعية: الوحدات والمنتجات والخامات والورديات والمناطق.
3. مستهدفات شهرية وربطها بالفترة/version؛ استيراد Excel التاريخي.
4. تسجيل الخام والمنتجات وحالة الوحدة لكل يوم/وردية عند توفر البيانات.
5. تسجيل وإدارة توقف مخطط/غير مخطط وإعادة التشغيل.
6. تحليل Actual/Target وإنتاج تقارير شهرية و3 KPI رئيسية.
7. مدقق بيانات تاريخية واستعداد AI، وخط أساس تنبؤ.
8. XGBoost مقارنة بالـbaseline فقط إذا اجتازت البيانات متطلبات التدريب.
9. Dynamic reforecast بعد تغيّر حدث، مع Scenario للمدة غير المعروفة.
10. Dashboard حسب الدور، Alerts، PDF/Excel export عند الصلاحية.
11. دورة إعادة تدريب وحوكمة على مستوى MVP-lite (قد تبدأ يدويًا في التجربة).

## خارج نطاق MVP

- التحكم الفعلي في أجهزة التحكم الموزع أو السلامة أو إجراء setpoints.
- Predictive Maintenance لأعطال قبل وقوعها بدون بيانات حساسات؛ موضوع منفصل.
- تحسين أوتوماتيكي لتوزيع الخام/خلطة البنزين أو توصيات تشغيل ملزمة.
- تكامل live DCS/OPC/SCADA دون إذن OT security وتقييم مخاطر.
- محاسبة المخزون والمبيعات والكلفة المالية التفصيلية.

## رحلات المستخدم (User Journeys)

**U1**: تخطيط يحدد Target لسبتمبر → مسؤول يعتمد النسخة → يظهر المستهدف في Dashboard.

**U2**: وردية إنتاج تُدخل الخام والمنتجات وساعات التشغيل → مراجعة/اعتماد → تحديث جدول المراقبة وKPI.

**U3**: هندسة عمليات تفتح انخفاض الديزل عن الخطة → ترى التوقفات وfeed وloss والاتجاه السابق → تضيف تفسيرًا مرجعيًا → ينشأ تقرير شهري.

**U4**: Trip غير مخطط للوحدة → event يبدأ بوقت معلوم → ينطلق reforecast → يظهر أثر الحدث وتاريخ as_of وفرضية ETA → إدارة التشغيل تقيّم خطر الهدف.

**U5**: إعادة تشغيل قبل ETA → حدث يُغلق → reforecast جديد لا يمحو التوقع السابق → تظهر مقارنة توقع قبل/بعد.

**U6**: وصول Actual أيام جديدة → سجل Approved → Dataset snapshot → تدريب Challenger → تقييم وقرار نشر/رفض → حفظ history.

## مؤشرات نجاح منتج غير مضمونة مسبقًا

- زمن إعداد التقرير: baseline يقاس من فريق المصفاة قبل/بعد.
- نسبة سجلات موثقة المصدر ومكتملة، قيمة مستهدفة تحدد بعد Audit.
- انخفاض أخطاء الإدخال والتكرار مقارنة بخط الأساس.
- Accuracy improvement: شرط قياسي واقعي بعد Baseline، **لا تعد به الآن**.
- Event reforecast latency: SLO محدد بعد قياس الأحمال وموافقة الإدارة.

## سياق النجاح الأكاديمي

وجود workflow كامل، baseline منافس، اختبار زمني بلا leakage، توثيق Feature Lineage، تفسير قابل للتدقيق، وحدود واقعية للسلامة؛ أهم من اختراع رقم دقة جذاب.
