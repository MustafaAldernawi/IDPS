# 22 — القرارات المعتمدة لتطوير IDPS مع البيانات الحالية (v1.2)

**القرارات مثبتة من حديث صاحب المشروع**:

- اسم المنظومة **IDPS**, العنوان العربي الرسمي كما في README.
- DB **MySQL**؛ مرجع التطوير MySQL 8.4 LTS.
- Training Studio يدخل V1 **في البرمجة والتشغيل التجريبي**، وليس مجرد خارطة طريق V2.
- ابدأ بالبيانات الحقيقية المتاحة من 2021–2023 (monthly) كمستوى أول؛ لا توجد بيانات يومية تاريخية مؤكدة.
- اسمح برفع DataSet أخرى لاحقًا (monthly/daily/shift)، ثم train/evaluate/registry/prediction حسب جودتها.
- بعد إدخال Actuals جديدة *ومراجعتها*، أضفها لسجل التدريب مع `available_at`; درّب challenger عند الطلب أو شهريًا ثم قارنه مع baseline وchampion؛ لا استبدال تلقائي بمجرد إدخال صف.
- لا تعد بدقة محددة، ولا تخدع المستخدم بأن baseline أو research model يساوي AI متحققًا للتشغيل.
- التوقفات المفاجئة: كشف/تسجيل بعد حدوثها، إعادة توقع، سيناريوهات ETA؛ لا predictive-maintenance claim دون مستشعرات وقصص أعطال.
- الحد الأساسي للمنتجات LPG، نافثا غير معالجة، جازولين، كيروسين، ديزل، زيت وقود ثقيل، وإسفلت عندما تتوفر labels وscope منفصلة.

**ما لا يُعد قرارًا مُصدقًا هندسيًا بعد**: نهاية اليوم التشغيلي، تعريف فاقد المصفاة، طريقة حساب SEC الحقيقي، نهائية نسب الـAssay للزمن الحالي، حد قبول نموذج ML ومعلومات source revisions لعام 2023.

**الأثر على المراحل القديمة**: لا تربط بدء التنفيذ أو تدريب candidates بتاريخ يومي 3 سنوات. لا تزال *ترقية أي نموذج إلى production* مشروطة بالمراجعة والتقييم. المسار الأول شهري، وبعد إضافة daily data لاحقًا تنشأ scope جديد وليس تغيير تعريف السجلات الشهرية.
